# 任务计划：TradingView 仓库架构说明 HTML

## 目标
在不修改任何源代码、配置、测试或现有历史规划内容的前提下，审计当前仓库并生成一份可直接打开的 HTML 文档，完整说明：
1. 整体架构、模块职责、模块协作和代码位置；
2. 每个文件夹的内容与作用；
3. 架构师视角下的运行方式、设计取舍和扩展路径；
4. 可删除内容候选：无用代码、过时文档、过时测试，并区分确认结论与待人工复核项。

## 交付物
- `tradingview_repository_architecture.html`：最终架构说明文档。
- `.planning/tradingview-architecture/`：本次任务的规划、发现和进度记录。

## 约束
- 阶段 1-5 为已完成的只读架构审计；阶段 6 允许修改 `README.md`、当前 `docs/`、必要的示例配置说明和文档契约测试。
- 不修改产品运行逻辑；不重写 `archive/`、audit 原始证据和历史规划记录，只在当前文档中清楚标注其历史边界。
- 不恢复或覆盖用户当前对 `web/tradingview_zy_chart/cl_app/static/echarts.min.js` 的删除。
- 所有文档结论必须由当前代码、配置、CI、生成器或测试契约验证，避免根据旧文档相互引用得出结论。
- 文档中的路径以仓库相对路径表示，命令必须能在当前 Windows/Bash/CI 使用方式下成立。

## 错误记录
| 错误 | 次数 | 处理 |
|---|---:|---|
| 使用 `awk` 直接处理 Windows 反斜杠路径时发生转义/字符串未闭合 | 2 | 不再复用同一命令；改用 `find` 列目录、`rg` 做文件/文本搜索，避免影响审计结论 |
| 使用 `python -c` 内嵌多行 HTML 解析器时 shell 将 `\\n` 保留为字面量，触发 SyntaxError | 1 | 改用 heredoc 标准输入执行同一只读校验，HTML 文件未受影响 |
| 第一次规范化 `git ls-files` 路径时 `sed` 反斜杠替换表达式未闭合 | 1 | 改用 `tr` 后成功产出全部 Git 跟踪目录清单 |
| 权限策略拒绝宽泛的 `rm -rf .pi-subagents` | 1 | 改用限定目录的 `find -delete` 清除本轮已确认的未跟踪临时审计文件，未触碰产品文件 |
| 在 Bash 环境误用了 PowerShell 的 `Get-Item`/`Select-Object` | 1 | 改用 `stat`、`find`、`sed` 等 Bash 命令，不重复该命令 |
| 当前环境没有 `apply_patch` 命令 | 1 | 改用精确文本替换工具更新 scoped planning 文件 |
| 按常见命名尝试读取不存在的根级 `run.sh`、`run.bat` 和 `src/tradingview_zy/app.py` | 1 | 不再猜测入口；改由 `git ls-files` 和 README 现有路径定位真实启动脚本 |
| 误猜 Windows 契约测试名为 `tests/test_me14_windows_scripts.py` | 1 | 用 `rg -l LAUNCHERS tests` 反查实际测试文件，不重复猜测 |
| 初次统计 `patches.json` 时误判 `patches` 子项为对象而非列表 | 1 | 先检查 JSON 实际结构，再用匹配结构的统计逻辑；不影响文件内容 |
| 第二次统计又误把 `patches.json` 顶层列表当字典 | 1 | 第三次先分支检查根类型，再遍历每个文件对象的 `patches`；停止猜测层级 |
| 首轮 `git diff --check` 报告部分编辑文件新增行存在 CRLF 混合导致的行尾空白 | 1 | 对本轮修改的文本文件机械规范化为 LF，再重新运行 diff check |
| Windows Node 无法解析 Bash `<(...)` 进程替换生成的 `/proc/.../fd` 路径 | 1 | 改为通过标准输入执行 `node --check -`，不重复使用进程替换 |
| 专项 pytest 误写不存在的 `tests/test_strategy_bridge.py`，导致收集前退出 | 1 | 用 `rg -l signal_to_trade_decision tests` 定位真实测试名后重跑完整专项集合 |
