- 退役日期：2026-09-29。

- 状态：**仅供恢复与研究，不是受支持的运行时模块**。归档不参与 Python import、打包或 pytest 收集。

## 为什么退役

监控策略迁移后，飞书发送函数已不在告警执行链上；设置页与任务“发送消息”开关仍在，形成误导。另一方面，数字货币适配器为读取代理配置而导入 `utils.py`，会连带加载大型 `lark_oapi` SDK。退役后 `utils.py` 只保留代理读取；移除飞书配置界面、SDK、专属重试/配置迁移代码及不再适用的测试。

## 保存了什么

ZIP 按原仓库相对路径保存修改前的通知实现、配置模板、设置/任务前后端、共享 Secret/DB/服务装配文件、相关回归测试、依赖声明与锁文件、安全门禁和现行说明。`MANIFEST.json` 列出完整清单与 SHA-256；`RESTORE.md` 是本说明的副本。

**不包含**私人 `config.py`、环境变量值、任何数据库、用户行情、飞书凭据、`DATA_PATH/secrets` 或安装后的第三方 SDK。共享文件是历史快照，不代表恢复时应该整文件覆盖。

## 保留的兼容数据

本次只移除代码及配置模板，不主动删除用户已有的 `fs_keys` 缓存、`DATA_PATH/secrets/feishu` 私有文件、旧任务表 `is_send_msg` 物理列或私人配置字段。它们不再被运行时代码读取或使用，不会回显到设置页。尤其老版本可能留下明文 `fs_app_secret`：退役后不会自动访问/迁移这些值；若不再需要，可由部署者在备份和确认后清理旧数据，并在飞书平台撤销机器人凭据。不要把凭据连同源码归档。

代理设置、登录/CSRF、通用 Secret 引用和脱敏设施、监控策略执行及告警入库仍保留；应用不再宣称支持内置外部消息通知。未卸载当前机器环境中的包；更新环境时 `uv sync --locked` 会按新锁文件同步，不再要求安装飞书 SDK。

## 恢复步骤（必须重新审查，不能直接覆盖）

1. 解压到新的临时目录，验证 `MANIFEST.json` 的 SHA-256，先阅读原 `utils.py`、`settings_security.py`、`messaging_reliability.py` 与测试。
2. 把飞书实现放入**独立可选通知模块**，SDK 只在启用并发送时惰性导入。不要恢复 `utils.py` 顶层 SDK import；代理工具不能依赖通知 SDK。
3. 对照当时锁文件（`lark-oapi==1.7.2`）审查许可证、漏洞和当前 SDK 契约后，增加可选依赖并重新生成依赖锁、SBOM 与供应链摘要；不要整份覆盖旧 `uv.lock`。
4. 在当前任务/配置协议中重新设计显式启停及逐市场路由；不要覆盖已修复的 DB 迁移、唯一约束、CSRF 和通用监控接口。旧 `is_send_msg` 列仅是遗留数据，不是现成通知能力。
5. 恢复 reference-only 凭据、首次迁移、空值保持、轮换与脱敏测试。须保持服务端保存、浏览器不回显 Secret；旧凭据可能已撤销，不要默认重新启用。
6. **重新接入告警执行链**：原快照里的 `send_fs_msg` 就没有被 `alert_run` 调用。恢复文件本身不会恢复推送。告警持久化与外部发送解耦，发送故障不能阻止入库；保持有限超时/重试与幂等 delivery UUID，避免重复通知。
7. 在临时数据库/假 SDK 下恢复适用测试，补真实前端设置与通知链测试；经明确授权后再做测试机器人联调。除飞书外，代理/监控/选股/行情功能都需回归。

历史 `audit/`、`remediation_report.md` 等保持原样，记录它们当时的事实；本文件和 `docs/messaging-channels.md` 描述当前退役状态。
