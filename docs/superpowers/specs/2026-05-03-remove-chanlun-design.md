# 剥离缠论模块并迁移为 tradingview_zy 设计

## 背景与目标

项目当前以缠论分析为核心，同时包含行情接入、K 线数据、Web 图表、交易执行、回测、选股和监控等能力。本次改造目标是彻底剥离运行路径中的缠论模块，将项目迁移为 `tradingview_zy` 通用行情/交易/Web 工具，同时尽量保留非缠论功能正常运行。

验收以服务级能力为准：Web 服务可启动，基础 K 线接口可用，行情同步脚本可运行；尽量覆盖通用回测最小示例和 trader 核心类 import。

## 设计原则

- 一次性将运行包名从 `chanlun` 迁移为 `tradingview_zy`。
- 不保留旧 `chanlun` 包兼容层，避免隐藏依赖。
- 不采用运行时继续计算后隐藏结果、空跑过滤等消耗性能的剥离方式。
- 缠论源码不保留在运行源码树，仅压缩归档到 `archive/`。
- 缠论相关文档迁入 `archive/docs/`，主文档只描述新项目能力。
- 选股和监控保留通用接口、任务入口和 Web/API 外壳，但移除缠论实现。

## 架构

运行源码树保留以下非缠论能力：

- 交易所适配、K 线查询、股票/合约列表、数据存储。
- 基础 Web TradingView UDF 接口和普通 K 线图表展示。
- 交易执行适配，包括下单、撤单、账户、持仓等能力。
- 通用回测框架，包括账户、撮合、订单、持仓和绩效输出。
- 通用选股与监控接口，用于对接自定义策略。

一次性迁移范围：

- `src/tradingview_zy/` 迁移为 `src/tradingview_zy/`。
- `web/tradingview_zy_chart/` 迁移为 `web/tradingview_zy_chart/`，并只保留基础图表/K 线服务入口及通用选股/监控外壳。
- `src/cl_myquant`、`src/cl_vnpy`、`src/cl_wtpy`、`joinquant` 等缠论策略适配下线或归档。
- 缠论计算、缠论接口数据结构、分型、笔、线段、中枢、买卖点、背驰、缠论图形绘制从运行路径移除。

## 组件设计

### 行情与数据层

`tradingview_zy.exchange`、`db`、`file_db` 保留交易所适配、K 线查询、列表查询和数据存储能力。返回值只使用普通行情、K 线、订单等通用数据对象，不依赖缠论结构。

### Web 层

`web/tradingview_zy_chart` 保留登录、基础图表、TradingView UDF 接口、基础自选/行情页面。删除缠论图形、买卖点、背驰、中枢等页面入口和路由。

选股/监控页面保留为“策略结果/监控任务”外壳，用于展示自定义策略输出，而不是展示缠论分析结果。

### 策略接口层

新增或改造通用 `Strategy` 协议。策略输入为普通行情数据，例如 K 线、行情快照、账户或持仓上下文；输出为统一结果，例如信号、标签、分数、原因、目标标的、触发时间或交易操作。

选股、监控、回测和交易尽量复用同一策略接口，避免每个场景维护独立适配。

### 选股与监控层

保留原任务调度和入口，但内部从“调用缠论分析”改为“加载自定义策略并执行”。监控框架只负责调度、数据获取、结果记录和通知，不内置缠论分析。

### 回测与交易层

回测保留账户、撮合、订单、持仓等通用能力，删除缠论策略示例。原来依赖 `get_cl_data()` 的流程改为普通 K 线访问。

实盘 trader 保留下单、撤单、账户查询、持仓查询等执行能力。trader 不关心信号来源，只消费统一信号或操作对象。

### 归档与文档

新增文档：

- `docs/web-right-panel-extension.md`：说明如何在 Web 端右侧添加扩展窗口。
- `docs/custom-strategy-integration.md`：说明自定义策略如何接入选股、监控、回测和交易。

缠论文档迁到 `archive/docs/`。缠论源码压缩归档到 `archive/`，不参与 import、不参与运行。

## 数据流

### Web K 线展示

浏览器 TradingView 图表请求 UDF 接口，Web 路由解析市场、代码和周期，调用 exchange 获取普通 OHLCV K 线并返回。流程不再计算或叠加分型、笔、线段、中枢、买卖点等图层。

### 选股流程

选股任务读取股票池或标的列表，批量获取普通 K 线或行情快照，调用用户配置的自定义策略。策略返回统一选股结果后写入结果存储，并由 Web 页面展示。

性能上只按策略声明所需的数据范围取数，避免先运行缠论分析再过滤。

### 监控流程

监控任务按配置周期拉取行情，调用自定义策略判断触发条件，生成监控事件并记录或通知。监控框架只负责调度、数据获取和结果分发。

### 回测流程

回测引擎读取历史 K 线，调用通用策略接口生成信号或操作，撮合成交，更新账户和持仓，最终输出绩效。

### 交易流程

行情源、选股或监控任务产生策略信号后，由 trader 适配层执行下单、撤单或查询，并记录交易结果。信号可以来自均线、机器学习、外部规则或其他自定义策略。

## 错误处理与降级

### 旧缠论入口

不做兼容转发，不在运行路径保留 `chanlun` 包。脚本中仍保留的缠论入口统一改为明确提示：“缠论模块已移除，请改用自定义策略接口”，然后正常退出，避免 import 阶段崩溃。

### Web 已删除页面

删除导航入口和路由。如果用户直接访问旧缠论页面，返回 404 或简短移除说明，不触发后台计算。

### 自定义策略加载失败

记录具体模块名、类名和异常信息，并按场景跳过该策略或终止当前任务。不使用默认策略兜底，避免产生误导结果。

### 策略输出不符合协议

只在外部策略接入边界做轻量校验，例如字段缺失、类型错误、非法操作。内部循环不做重复重校验，避免性能损耗。

### 数据不足或行情源异常

行情层返回明确错误或空数据。调用方按场景处理：Web 返回空 K 线响应，选股/监控记录失败标的，回测终止或按配置跳过。

### 包名迁移遗漏

所有项目内 import 一次性替换为 `tradingview_zy`。验收时通过 import 检查、Web 启动和脚本启动级检查暴露遗漏。

## 测试与验收

### 基础导入检查

验证 `tradingview_zy` 核心模块可 import，包括行情、配置、Web 依赖、交易执行核心类、通用回测核心类。确认运行路径不再依赖 `chanlun` 包。

### Web 服务检查

启动 `web/tradingview_zy_chart/app.py`，确认服务能启动。检查 TradingView UDF 关键接口：

- `/tv/config`
- `/tv/search`
- `/tv/symbols`
- `/tv/history`

### 行情同步脚本检查

对保留的行情同步脚本做 import 或启动级检查。缺配置或缺外部服务时应给出清晰错误，而不是旧缠论 import 崩溃。

### 选股/监控接口检查

用一个最小自定义策略样例验证：

- 选股任务能加载策略并输出结果。
- 监控任务能加载策略并生成事件。
- 失败策略能产生清晰错误。

### 回测/交易尽力验收

尽量提供普通 K 线策略的最小回测示例。验证 trader 核心模块可 import，下单接口类可实例化或至少不因缠论依赖失败。

### 文档验收

检查以下文档存在且内容可执行：

- `docs/web-right-panel-extension.md`
- `docs/custom-strategy-integration.md`

## 实施顺序建议

1. 创建 archive，并压缩归档缠论源码，迁移缠论文档。
2. 重命名包和 Web 目录，批量替换项目内 import。
3. 删除缠论计算、图形、策略实现和页面入口。
4. 改造选股/监控为通用策略接口。
5. 改造回测策略接口和 trader 信号入口。
6. 更新脚本入口提示和文档。
7. 按验收标准运行导入、Web、UDF、脚本和最小策略检查。
