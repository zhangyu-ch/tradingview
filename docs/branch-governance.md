# 分支治理

## 当前主线

`main` 是唯一的开发、集成和发布分支，也是 GitHub 默认分支。新的功能、修复、CI 和部署配置只能以 `main` 为目标。

## `master` 归档基线

`master` 是原始远端基线，与 `main` 没有共同祖先。它只用于审计、历史对照和问题复核，不是开发分支、发布分支、回滚分支或 PR 合并目标。

远端已将 `master` 锁定为只读：禁止直接推送、强制推送、删除和通过 PR 合并写入。仓库中的现行 CI 只监听 `main`，不应新增以 `master` 为目标的工作流、徽章、脚本或部署配置。

## 审计使用方式

审计时可显式比较两个快照，例如：

```bash
git diff master main -- <path>
git show master:<path>
```

由于两条历史没有共同祖先，禁止将 `master` 合并或 rebase 到 `main`；需要研究旧实现时，应从 `master` 创建临时审计分支，并将结论或重新实现的修复通过面向 `main` 的 PR 提交。

## 例外流程

任何改变 `master` 的操作都必须先得到仓库管理员的明确批准，并记录原因、影响范围和恢复方案。需要恢复旧代码时，在新的迁移分支中重新实现或摘取经过审查的变更；不得解锁 `master` 作为日常开发或发布路径。
